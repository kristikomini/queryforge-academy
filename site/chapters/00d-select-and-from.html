Your first query: SELECT and FROM

Two keywords, one statement, and every token in it explained — including the semicolon.

No advert asked for this

It is the first statement anybody writes. Written out here token by token so that nothing in it is ever a mystery again — and so that the anatomy panel under every later example reads as a reminder rather than as a foreign language.

The smallest complete query

🧒 Simple

A query is one sentence with two halves. The second half says which pile of cards to look in. The first half says which boxes on the card you want to see. That is genuinely all a basic query is: where to look, and what to show.

🎓 Professional

SELECT is a projection: it chooses columns and can compute new ones. FROM names the row source. Written in that order, evaluated in the opposite one — the engine resolves FROM first, because SELECT cannot mean anything until it knows which columns exist. That inversion is the root of most beginner errors, and chapter 06 is devoted to it.

A layout convention worth adopting on day one

  1. SELECT chooses columns, FROM names the row source — and the engine resolves FROM first, whatever the writing order says.
  2. SELECT * is for exploring. Name the columns in anything you save: it survives schema change, moves less data, and can be served by an index.
  3. An alias renames a column in the result only, and a computed column needs one or it has no usable name.
  4. Single quotes are for text; double quotes (or brackets in SQL Server) are for identifiers.
  5. Database error messages are literal, and the position they report is where the parser gave up — look at the token before it.
  6. One column per line, keywords starting the line, tables aliased: the layout is what makes a query reviewable.

Why is SELECT * discouraged in production code?

It is expanded at parse time, so the result changes silently when the table does; it fetches columns nobody asked for, including large ones; it prevents a narrow index from covering the query; and it hides the query's intent from the next reader. At an interactive prompt, while exploring, it is exactly the right tool.

What is the difference between 'name' and "name" in a query?

Single quotes make a text literal — the five characters n-a-m-e. Double quotes make a quoted identifier — a column or table called name. So WHERE city = 'Modena' compares against text, while WHERE "city" = Modena compares two columns and fails. SQL Server also accepts [brackets] for identifiers, and MySQL `backticks`.
