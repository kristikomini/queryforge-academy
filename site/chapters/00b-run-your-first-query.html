Getting a database in front of you

Four ways to have a working SQL engine in under a minute, and your first statement run in each.

No advert asked for this

Nobody is hired for installing a database. But a course you cannot run is a book, and the single most common reason beginners stop is that nothing ever actually ran. Ten minutes here removes that failure mode permanently.

Two programs, and people confuse them constantly

🧒 Simple

There are two pieces. One is the filing cabinet with the assistant in front of it — it holds everything and does the work. The other is the notepad you write your requests on. Installing a very nice notepad does not give you a filing cabinet, which is why “I installed the SQL program but there is no database” is such a common first afternoon.

🎓 Professional

The engine is a server process that owns the data files and executes statements: SQL Server, PostgreSQL, MySQL, Oracle. The client connects to it over a socket, sends statements and renders results: SSMS, DBeaver, Azure Data Studio, psql. They are separate choices, they are versioned separately, and a connection failure is almost always one of three things — host, port, credentials — in that order. SQLite is the exception that clarifies the rule: it is a library the client links against, so there is no server and no connection at all.

Option 1 — the playground, which is already open

This site ships a real SQL engine: SQLite, compiled to WebAssembly, 700 KB, served from this folder. It runs in the browser tab, needs no installation and no network, and it comes with the course's reference database already loaded — eleven tables of a plausible order-fulfilment system.

✔ Do this now

Open the playground, and press Run. Something will appear. That is the whole of this option, and for the first three parts of the course it is enough.

Option 2 — SQLite on your own machine

The playground's engine, as a single executable with no server, no configuration and no account. This is the right choice for working through the course on a laptop, and for keeping your own scratch database.

Option 3 — a real server engine, in one Docker command

From chapter 21 onwards, some things simply cannot be shown in SQLite: it has one writer, so there is no locking, no blocking and no isolation levels to observe. When a chapter needs a server engine it says so, and this is the command.

Option 4 — a client you will actually enjoy

The engine stores the data; a client is the program you type into. They are separate choices, and a good client makes learning noticeably faster because it shows you the schema while you work.

⚠ The one setting to change on day one

Most clients run in autocommit: every statement is committed the instant it finishes. That means a DELETE with a mistaken WHERE clause is permanent before you have finished reading it. Learn where your client's “begin transaction” button or setting is, and read chapter 0H before running your first DELETE against anything you would miss.

If nothing works

  • The playground says the engine will not start. WebAssembly may be blocked by a policy or an extension, or the page was opened from file:// in a browser that refuses local .wasm. Run node tools/serve.mjs and open http://localhost:4321.
  • “command not found: sqlite3”. The install did not put it on your PATH. Reopen the terminal first; that fixes it more often than anything else.
  • Docker says the port is already in use. Something else is on 5432 — often a previous container. Publish a different one: -p 5433:5432, and connect to 5433.
  • You cannot connect to a server that is definitely running. Nine times in ten it is the host (localhost versus 127.0.0.1), the port, or the password — in that order. Read the error message aloud; database error messages are unusually literal.

What is the difference between a database engine and a client?

The engine is the server process that owns the data files and executes statements. The client is the program you type into, which sends statements over a connection and renders the results. SSMS is a client; SQL Server is the engine. Confusing the two is why “I installed SSMS but there is no database” is such a common first question.

Why does this course use SQLite when the adverts ask for SQL Server?

Because it removes the installation step entirely, and because Parts 1 to 3 run identically on both. Where SQLite genuinely cannot demonstrate something — isolation levels, locking, real cost-based plans — the chapter says so and gives the Docker command for an engine that can.
