CASE, COALESCE and conditional aggregation

How to pivot without PIVOT, and why conditional aggregation beats five self-joins every single time.

From the advert

“Reporting con SSRS e Power BI” — nine tenths of report work is turning rows into columns and putting a label on a number. That is this chapter.

CASE: the only conditional you need

-- Searched CASE: any predicate, evaluated top to bottom, FIRST match wins.
SELECT id,
       CASE WHEN total_cents >= 100000 THEN 'large'
            WHEN total_cents >=  20000 THEN 'medium'
            ELSE 'small'                                   -- omit ELSE and you get NULL
       END AS bucket
FROM orders;

-- Simple CASE: equality against one expression. Cannot test NULL (nothing equals NULL).
CASE status WHEN 'draft' THEN 'Bozza' WHEN 'shipped' THEN 'Spedito' ELSE status END
⚠ Trap

Order matters and there is no warning. Put WHEN total >= 20000 before WHEN total >= 100000 and every large order is labelled medium — the query runs, returns rows, and the report is quietly wrong. Write the branches from the most specific downwards, and always include an ELSE so an unhandled value is visible rather than a null nobody looks at.

Pivot without PIVOT

🧒 Simple

Your data is a long list: “January, Modena, 40”. The boss wants a grid with months down the side and cities across the top. Turning the list into the grid is a pivot — and the trick is just to make one column per city that only adds up the numbers belonging to that city. 

-- Portable everywhere, readable, and the answer to give in an interview.
SELECT
  DATE_TRUNC('month', o.placed_at)                                    AS month,
  SUM(CASE WHEN c.city = 'Modena'  THEN o.total_cents ELSE 0 END)/100 AS modena,
  SUM(CASE WHEN c.city = 'Parma'   THEN o.total_cents ELSE 0 END)/100 AS parma,
  SUM(CASE WHEN c.city = 'Bologna' THEN o.total_cents ELSE 0 END)/100 AS bologna,
  SUM(o.total_cents)/100                                              AS total
FROM orders o
JOIN customers c ON c.id = o.customer_id
GROUP BY DATE_TRUNC('month', o.placed_at)
ORDER BY month;
🎓 Why not the PIVOT operator?

SQL Server and Oracle have a PIVOT keyword. It is shorter for simple cases and it is not portable, it only handles one aggregate, and it still needs the column list written out — so it solves none of the real problem. Conditional aggregation works in every engine, supports several different aggregates side by side, and is easier to read. Know that PIVOT exists; reach for CASE.

The column list must be static

SQL returns a fixed set of columns decided at parse time, so a pivot over “whatever cities exist” requires dynamic SQL — building the statement from the data and executing it. That is a real technique with a real injection risk, and it is usually the wrong answer: let the reporting tool pivot. Power BI, SSRS and Excel all pivot a long result natively, and returning long data keeps the query static, cacheable and safe. Saying this is a better answer than writing the dynamic SQL.

Unpivot: grid back into list

You will meet this cleaning up a spreadsheet import, where somebody has columns jan, feb, mar…: 

-- Portable: one branch per source column, stapled with UNION ALL.
SELECT product_id, 1 AS month, jan AS qty FROM sales_wide WHERE jan IS NOT NULL
UNION ALL SELECT product_id, 2, feb FROM sales_wide WHERE feb IS NOT NULL
UNION ALL SELECT product_id, 3, mar FROM sales_wide WHERE mar IS NOT NULL;

-- PostgreSQL, more compact and one pass over the table:
SELECT product_id, m.month, m.qty
FROM sales_wide
CROSS JOIN LATERAL (VALUES (1, jan), (2, feb), (3, mar)) AS m(month, qty)
WHERE m.qty IS NOT NULL;

COALESCE and NULLIF in reports

SELECT
  COALESCE(c.company_name, c.first_name || ' ' || c.last_name, 'Unknown') AS display_name,
  -- Division that cannot fail, and returns NULL rather than a fake zero:
  ROUND(100.0 * o.delivered / NULLIF(o.total, 0), 1)                      AS delivery_pct,
  -- Treat empty string as missing (the classic import artefact):
  COALESCE(NULLIF(TRIM(c.vat_number), ''), '—')                           AS vat
FROM customers c ...
⚠ Trap — COALESCE vs ISNULL in T-SQL

ISNULL(a, b) returns the type of a, so ISNULL(short_col, 'a long default string') silently truncates the default. COALESCE uses type precedence across all arguments and does not. COALESCE is also standard SQL. Use it.

The reporting shape you will be asked for

-- "Monthly order status breakdown with percentages" — the archetypal SSRS/Power BI
-- backing query. Conditional aggregation, one scan, no subqueries.
SELECT
  strftime('%Y-%m', placed_at)                                 AS month,
  COUNT(*)                                                     AS orders,
  COUNT(CASE WHEN status = 'delivered' THEN 1 END)             AS delivered,
  COUNT(CASE WHEN status = 'cancelled' THEN 1 END)             AS cancelled,
  ROUND(100.0 * COUNT(CASE WHEN status = 'cancelled' THEN 1 END)
        / NULLIF(COUNT(*), 0), 1)                              AS cancel_pct,
  SUM(CASE WHEN status <> 'cancelled' THEN total_cents ELSE 0 END)/100.0 AS revenue_eur
FROM orders
GROUP BY month
ORDER BY month;
  1. CASE branches are evaluated in order and the first match wins. Order them most specific first.
  2. Always write an ELSE. A missing one produces nulls that nobody investigates.
  3. Simple CASE cannot match NULL, because nothing equals NULL.
  4. Pivot with conditional aggregation: portable, multi-aggregate, readable. PIVOT is shorter and non-portable.
  5. The column list of a pivot is fixed at parse time. A dynamic pivot needs dynamic SQL — usually let the reporting tool do it instead.
  6. Unpivot with UNION ALL, or a lateral VALUES list for one pass.
  7. NULLIF(x, 0) is the division guard; NULLIF(TRIM(x), '') normalises empty strings to missing.
  8. Prefer COALESCE to ISNULL: standard, n-ary, and it will not truncate your default.

Interview questions this chapter answers

Pivot monthly sales into one column per region.

Conditional aggregation — one SUM(CASE WHEN region = 'x' THEN amount ELSE 0 END) per region, grouped by month. I would mention that the region list has to be static, and that if it is genuinely dynamic the right answer is usually to return long data and let the reporting layer pivot it.

Difference between COALESCE and ISNULL?

COALESCE is standard, takes any number of arguments, and determines the result type from all of them. ISNULL is T-SQL, takes two, and returns the first argument's type — so it can silently truncate the replacement value.

How do you avoid divide-by-zero in a percentage column?

NULLIF(denominator, 0). Dividing by null yields null, which is the honest answer for “undefined”, and no error is raised. Wrapping it in COALESCE(…, 0) is a separate decision about how to display it.
