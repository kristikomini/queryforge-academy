WHERE: asking for less

Comparison operators, AND, OR, NOT, IN, BETWEEN, LIKE — and the first place NULL will surprise you.

No advert asked for this

A query with no WHERE clause reads the whole table. Learning to say what you actually want is the first performance lesson of the course, disguised as a syntax lesson.

One condition, evaluated once per row

🧒 Simple

Go through the pile of cards one at a time. For each card, ask a yes-or-no question. Keep the yeses, throw away the noes. WHERE is that question, and it is asked once per card.

🎓 Professional

WHERE takes a boolean expression evaluated per row, and keeps the row only when the expression is TRUE. Not “not false” — TRUE. SQL has three truth values, and the third one, UNKNOWN, is produced by any comparison involving NULL; those rows are discarded exactly as though they had been FALSE. Logically the filter runs per row; physically the engine will use an index to avoid looking at most of them, which is what chapter 07 is about.

AND, OR and the brackets that decide the meaning

Ranges, lists and patterns

The first place NULL will surprise you

⚠ = NULL never matches anything

NULL means unknown. Is an unknown value equal to another unknown value? The honest answer is “unknown”, and that is exactly what SQL returns. WHERE keeps only TRUE, so the row is discarded — with no error, no warning, and a plausible-looking empty result.

The habit that keeps a filter fast

  1. WHERE keeps a row only when its condition is TRUE; UNKNOWN is discarded exactly like FALSE.
  2. AND binds tighter than OR. Bracket every mixture of the two, always.
  3. BETWEEN is inclusive at both ends, which makes it wrong for timestamps — use >= and <.
  4. A leading % in a LIKE pattern means a full scan, because an index is ordered by prefix.
  5. = NULL matches nothing; only IS NULL and IS NOT NULL can test for absence.
  6. col <> 'x' silently excludes rows where col is NULL.
  7. Keep the column bare on one side of the comparison, or the index cannot be used: that is sargability.

Why does WHERE shipped_at = NULL return nothing?

Because NULL means unknown, so the comparison evaluates to UNKNOWN rather than TRUE, and WHERE keeps only TRUE. IS NULL is the only operator that can test for absence. It is not an error, which is what makes it dangerous: you get a plausible empty result.

Why prefer >= '2026-03-01' AND < '2026-04-01' over BETWEEN?

Because BETWEEN includes both endpoints, and on a timestamp column the upper endpoint is midnight — so everything later that day is silently excluded. The half-open range is correct whatever the column's precision is now or becomes after a migration.
