Arithmetic in a SELECT, text and date literals, integer division, and CAST when the engine guesses wrong.

No advert asked for this

Integer division silently returning 0 is the single most common wrong number in a beginner's first report. It gets its own chapter for that reason, and because “which type is this expression?” is a question you will be asking for the rest of your career.

A SELECT list can compute, not just fetch

🧒 Simple

You do not only have to show what is written on the card. You can do sums with it on the way out: show the price divided by a hundred, or the first name and the last name stuck together. The card is never changed — you are just deciding what to write on the copy you hand over.

🎓 Professional

Every item in a SELECT list is an expression: a column reference is simply the simplest one. Each expression has a type, derived from its operands by the engine's type-precedence rules, and that derived type is what the client receives. Two identical-looking expressions can have different types — which is precisely why total_cents / 100 and total_cents / 100.0 return different numbers.

✔ How to learn the rest

Do not memorise a function list. Learn these twelve, and learn where your engine's documentation lists the others — then look them up. Interviewers ask what COALESCE does; they do not ask you to recite DATEADD's argument order, and being able to say “I would check the docs for the exact spelling” is a normal professional answer.

  1. Every item in a SELECT list is an expression with a type, derived from its operands.
  2. Integer ÷ integer truncates. total_cents / 100 loses the cents; / 100.0 does not.
  3. Single quotes make text, double quotes make identifiers, and an apostrophe inside text is doubled.
  4. A quoted date is text until something converts it; DATE '2026-03-14' is a typed literal, and ISO-8601 is the only format worth writing.
  5. Any arithmetic or concatenation involving NULL produces NULL — except functions defined otherwise, such as CONCAT and COALESCE.
  6. CAST in the SELECT list is free; a conversion on a filtered column costs you the index.
  7. CASE is an expression, its branches are tested in order, and omitting ELSE means non-matches are NULL.

A report shows every order as costing €0. What is the first thing you check?

Whether the query divides one integer by another — total_cents / 100 where both are integers truncates towards zero, so anything under a euro becomes 0 and everything else loses its cents. The fix is / 100.0, or an explicit CAST to a decimal type.

What is the difference between CAST and an implicit conversion?

CAST is written by you, is visible in review, and raises an error when the value will not convert. An implicit conversion is inserted by the engine when two types meet, follows precedence rules you did not choose, and — when it lands on an indexed column in a WHERE clause — silently turns a seek into a scan.
